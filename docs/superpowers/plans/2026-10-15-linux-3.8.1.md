# Zaper Linux 3.8.1 implementation plan

> Execute inline with verification after each feature and before publication.

**Goal:** Update the existing Linux preview against Windows Zaper 3.8.1 preserving Windows C# sources; fix repair ZIP path separators in the Windows build script after integration tests exposed that packaging defect.
**Architecture:** Preserve runtime/service/config identifiers for upgrades. Add a maintenance module for settings transactions, profiles/history, repair, downloads and diagnostics; keep GUI work outside the Tk event thread. Runtime networking stays on nfqws2 1.0.5.2, unchanged upstream.
**Tech Stack:** Python 3.10+ backend/Tk, nftables, optional pystray/Pillow for system tray, optional systemd.
**Spec:** Windows v3.8.1 README and src/Convenience.cs, Downloads.cs, HostsForm.cs plus user request to update Linux.

## Constraints

- Keep old CLI names, service, installation path and settings; expose Zaper branding and aliases.
- Never change host networking/Hosts/startup during development; perform privileged integration tests in isolated namespaces/containers.
- Windows-only EXE icons, SCM, task scheduler and installer logic must have Linux-native equivalents or explicit documented limits.
- Keep existing Linux preview gaps (auto-tune/proxy limiter) explicit; no claim of full Windows parity.
